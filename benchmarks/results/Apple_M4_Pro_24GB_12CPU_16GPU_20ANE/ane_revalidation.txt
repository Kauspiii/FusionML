=== ane_spike_test.py (dispatch overhead vs GPU) ===
======================================================================
  ANE Viability Spike Test
  Real CoreML/ANE execution vs CPU (Accelerate) vs GPU (MLX)
======================================================================

▶ ane_chunk_gpt2_ffn: [154x1600] @ [1600x6400]
  First call (incl. compile): 1010.9 ms
  ANE steady-state:  median=20.205 ms  std=6.071 ms
  CPU (Accelerate):  median=25.802 ms
  GPU (MLX):         median=1.140 ms
  Correctness: max_abs_err=1.35e-03  rel_err=1.60e-02
  ANE/GPU ratio: 17.72x (ANE slower)
  ANE/CPU ratio: 0.78x (ANE faster)

▶ cpu_chunk_gpt2_ffn: [256x1600] @ [1600x6400]
  First call (incl. compile): 840.8 ms
  ANE steady-state:  median=21.080 ms  std=7.007 ms
  CPU (Accelerate):  median=29.269 ms
  GPU (MLX):         median=2.656 ms
  Correctness: max_abs_err=1.19e-03  rel_err=1.49e-02
  ANE/GPU ratio: 7.94x (ANE slower)
  ANE/CPU ratio: 0.72x (ANE faster)

▶ full_gpt2_ffn: [1024x1600] @ [1600x6400]
  First call (incl. compile): 849.5 ms
  ANE steady-state:  median=25.065 ms  std=6.321 ms
  CPU (Accelerate):  median=69.460 ms
  GPU (MLX):         median=5.562 ms
  Correctness: max_abs_err=1.26e-03  rel_err=1.44e-02
  ANE/GPU ratio: 4.51x (ANE slower)
  ANE/CPU ratio: 0.36x (ANE faster)

======================================================================
  VERDICT
======================================================================
  ANE is SLOWER than GPU for every tested shape, even at steady-state
  (model compiled and cached). Adding ANE to the model-level scheduler
  would not help for these matmul sizes on this hardware.
