=== ane_spike_test.py (dispatch overhead vs GPU) ===
======================================================================
  ANE Viability Spike Test
  Real CoreML/ANE execution vs CPU (Accelerate) vs GPU (MLX)
======================================================================

▶ ane_chunk_gpt2_ffn: [154x1600] @ [1600x6400]
  First call (incl. compile): 1024.5 ms
  ANE steady-state:  median=23.850 ms  std=7.429 ms
  CPU (Accelerate):  median=25.993 ms
  GPU (MLX):         median=1.231 ms
  Correctness: max_abs_err=1.35e-03  rel_err=1.60e-02
  ANE/GPU ratio: 19.37x (ANE slower)
  ANE/CPU ratio: 0.92x (ANE faster)

▶ cpu_chunk_gpt2_ffn: [256x1600] @ [1600x6400]
  First call (incl. compile): 908.1 ms
  ANE steady-state:  median=24.086 ms  std=8.979 ms
  CPU (Accelerate):  median=32.422 ms
  GPU (MLX):         median=2.991 ms
  Correctness: max_abs_err=1.19e-03  rel_err=1.49e-02
  ANE/GPU ratio: 8.05x (ANE slower)
  ANE/CPU ratio: 0.74x (ANE faster)

▶ full_gpt2_ffn: [1024x1600] @ [1600x6400]
  First call (incl. compile): 916.5 ms
  ANE steady-state:  median=35.720 ms  std=6.927 ms
  CPU (Accelerate):  median=85.712 ms
  GPU (MLX):         median=6.040 ms
  Correctness: max_abs_err=1.26e-03  rel_err=1.44e-02
  ANE/GPU ratio: 5.91x (ANE slower)
  ANE/CPU ratio: 0.42x (ANE faster)

======================================================================
  VERDICT
======================================================================
  ANE is SLOWER than GPU for every tested shape, even at steady-state
  (model compiled and cached). Adding ANE to the model-level scheduler
  would not help for these matmul sizes on this hardware.
